# Contributing to DSA Visualizer

Thank you for considering contributing to DSA Visualizer! We welcome contributions from the community to make this project better for everyone learning Data Structures and Algorithms.

## 📝 How to Contribute

There are many ways to contribute to DSA Visualizer:

### 1. Report Bugs
Found an issue? Please report it using the [GitHub Issues](https://github.com/yourusername/DSA-Visualizer/issues) page. Include:
- A clear description of the problem
- Steps to reproduce the issue
- Expected vs actual behavior
- Screenshots or screen recordings if applicable
- Your browser and OS information

### 2. Suggest Features
Have an idea for a new algorithm, data structure, or feature? Open a feature request issue with:
- Clear description of the feature
- Why it would be useful
- Any mockups or examples if applicable

### 3. Contribute Code
We welcome pull requests for:
- New algorithm implementations
- New data structure visualizations
- UI/UX improvements
- Bug fixes
- Documentation improvements
- Performance enhancements

## 🔧 Development Setup

1. Fork the repository
2. Clone your fork:
   ```bash
   git clone https://github.com/yourusername/DSA-Visualizer.git
   cd DSA-Visualizer
   ```
3. Install dependencies:
   ```bash
   npm install
   ```
4. Start the development server:
   ```bash
   npm run dev
   ```
5. Create a new branch for your changes:
   ```bash
   git checkout -b feature/your-feature-name
   ```

## 📋 Pull Request Process

1. Ensure your code follows our coding standards
2. Write clear, descriptive commit messages
3. Update documentation if needed
4. Make sure existing tests pass
5. Add tests for new functionality
6. Submit your pull request with a clear description of changes

## 📏 Coding Standards

### TypeScript/JavaScript
- Use TypeScript for all new code
- Follow ESLint and Prettier configurations
- Use meaningful variable and function names
- Keep functions small and focused
- Add JSDoc comments for complex functions

### Component Structure
- Break down complex components into smaller, reusable ones
- Use functional components with hooks
- Separate concerns (logic vs presentation)
- Use proper TypeScript interfaces/types

### Visualization Code
- Algorithms should generate step-by-step visualizations
- Each step should clearly show what's happening
- Include operation counts (comparisons, swaps, etc.)
- Highlight relevant elements during operations

## 🧪 Testing

We use Vitest for testing. To run tests:
```bash
npm test
```

When adding new features, please include appropriate tests.

## 📚 Documentation

- Update README.md if your changes affect usage
- Add JSDoc comments for complex functions
- Update any relevant documentation files
- Consider adding examples or tutorials if appropriate

## 🎨 Design Guidelines

- Maintain consistent visual style
- Use the existing color scheme and typography
- Ensure visualizations are clear and easy to follow
- Make controls intuitive and accessible
- Support both light and dark themes
